# ADR-0008：去掉工作空间概念（一人一号一大屏 + 全站排名）

- 状态：已接受（用户于 2026-11-07 明确产品定位并选择"自动个人空间"方案）
- 日期：2026-11-07
- 关联：ADR-0005（多租户内核）、ADR-0007（听歌统计）、AGENTS.md §5（租户隔离铁律）

## 1. 决策

**自动个人空间（选定）**：注册时内核自动创建个人工作空间（`<昵称>的大屏`）并启用
dashboard 模块；前端移除工作空间切换器/创建/邀请等一切工作空间概念。
用户体验 = 一人一号、一号一大屏；小功能从大屏"功能"入口延伸。

**否决"彻底移除多租户"**：拆掉 workspace_id/RLS/模块网关属于天级重构，
且永久失去宪法 §2 的对外售卖能力。本方案在产品层消灭概念、在数据层保留隔离，
宪法 §5"所有业务表必须带 workspace_id"继续成立。

## 2. 关键实现

1. **注册引导（auth.controller.register）**：注册事务完成后自动
   `workspaceService.create(userId, { name: 昵称的大屏 })` + `moduleService.enable(ws, user, 'dashboard')`。
   开通失败不阻断注册（记日志，用户仍可手动启用）。slug 由 create 的 23505 重试保证唯一。
2. **全站排名**：`listeningRanking` 不再按 workspace 过滤。跨租户聚合经迁移 0008 的
   SECURITY DEFINER 函数 `platform.listening_ranking_global(start, end, limit)` 完成
   （以迁移属主身份绕过 listening_daily 的租户 RLS，只暴露 user_id/名称快照/总秒数，
   不泄露行级数据；EXECUTE 仅授 atlas_app）。
3. **前端**：侧栏移除 WorkspaceSwitcher（组件与相关 import 删除）；"工作空间"导航分组
   更名"更多"；根路径在 dashboard 启用时渲染大屏；**Shell 顶栏在根路径保留**
   （用户菜单/通知必须始终可达；也避免顶栏随模块查询结果挂载/卸载抖动），仅内容区全宽。
4. **统计页文案**："本空间排名"→"全站排名"。

## 3. 已知边界与后续

- 设置页仍保留"工作空间设置"（成员邀请等）界面 —— 底层能力未删，UI 收敛放到下一轮；
  命令面板/设置里的工作空间命名同步延后。
- 老用户（升级前注册）已有空间不受影响；多空间老用户取第一个作为活跃空间（切换器已摘）。
- 首启引导抽屉（未设城市）以模态拦截全页点击 —— 它在根路径加载约 1s 后弹出，
  自动化测试与真实用户都需先关抽屉再点顶栏（e2e 已统一处理）。
- 全站排名展示全部注册用户的昵称与听歌总时长；如后续需要隐私开关（匿名/退出榜）另立 ADR。

## 4. 迁移依赖边界（2026-11-08）

`platform.listening_weekly_report` 虽位于 `platform` schema，但只服务 dashboard 模块，且依赖模块表 `modules.dashboard.listening_daily`。因此函数与其授权应由 dashboard 模块迁移创建，排在该表迁移之后；内核迁移不得静态引用尚未安装的模块表。函数仍以 `SECURITY DEFINER` 绕过租户 RLS，只返回汇总字段，执行权限仅授予 `atlas_app`。

现有数据库已执行的内核迁移不会重跑；新的 dashboard 迁移会为已安装模块创建函数。回滚时先执行对应 `.down.sql` 删除函数，再卸载模块数据表。
