# OWASP Top 10 安全自审记录（2026-11-15）

> 路线图阶段 6「OWASP 完整审计」的自查落实。原则：每项结论给出代码/测试证据；
> 修复只做本次证据支撑的；面向未来售卖的风险记录为决策项而非提前实现。

## 逐项审查

### A01 失效的访问控制 — ✅ 无发现

- 所有业务控制器挂 `@UseGuards(AuthGuard)`：`ai` / `notifications` / `workspace` / `modules`（kernel 网关）四个控制器整体挂载，`auth` 仅公开端点（register/login/logout）豁免、`/me` 与邀请接受单挂。唯一公开的 `health` 只返回服务状态，无业务数据。
- 租户隔离：全部业务表带 `workspace_id` 且查询经 `withUser`（`set_config('app.user_id')` + RLS 两道防线，ADR-0005）；跨租户访问有集成测试覆盖（guest 403、模块权限）。
- 模块网关按 manifest 权限校验（如 `journal:write`），导入/导出动作均为只读或写权限对应检查（见 import-data.spec 8/8）。

### A02 加密失败 — ✅ 无发现

- 密码：Node 内置 scrypt（N=16384, r=8, p=1, 64 字节），每哈希独立盐，`timingSafeEqual` 比较，存储格式随参数可迁移（auth/password.ts）。
- 会话令牌仅存 `token_hash`（schema identity.ts），Cookie `httpOnly + sameSite=lax + secure(可配) + maxAge`（auth/cookies.ts）；会话带 `expiresAt` 与 `revokedAt`。

### A03 注入 — ✅ 无发现

- 全仓 `sql\`` 模板（drizzle）均为参数化绑定（`${var}` → 绑定参数），无字符串拼接；抽查 tenant.ts / event-dispatcher / notification 游标 / module.service / scheduler 共 12 处确认。动态排序等场景未见用户可控标识符拼接。

### A04 不安全设计 — ✅ 无发现（限流范围见决策项）

- 登录/注册限流：`auth:<ip>:<email>` 维度（rate-limit.service），防撞库与枚举。
- 删除默认软删除 + 回收站恢复；写操作审计（workspace/module 生命周期）。

### A05 安全配置错误 — 🔧 本轮加固 1 项

- 安全响应头已有：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy`、`Permissions-Policy`。
- **修复**：API 响应新增 `Cache-Control: private, no-store + Pragma: no-cache`——此前 GET 类端点（如通知列表）可入浏览器 HTTP 缓存；个人数据不该进 HTTP 缓存（前端数据缓存由 TanStack Query 客户端负责，不受影响）。已用 `curl -I /v1/health` 验证生效。
- CORS 显式 origin 白名单（非 `*`），credentials 按需开启。
- HSTS 与 CSP 属部署层/前端层配置：HSTS 随 HTTPS 上线（阶段 8 部署清单）；Next.js CSP 留部署轮评估（需处理 Next 内联脚本 nonce）。

### A06 易受攻击的组件 — ✅ 无发现

- `pnpm audit --prod --registry=https://registry.npmjs.org`：**No known vulnerabilities found**（npmmirror 镜像不支持 audit 端点，需指定官方源）。

### A07 认证失败 — ✅ 无发现

- 密码策略 ≥8 位（register schema）；登录失败限流同 A04；会话过期/吊销字段齐备；邮箱唯一索引 + 应用层小写归一化。

### A08 软件与数据完整性 — ✅ 无发现

- 无反序列化不可信数据场景；导出文件导入时经 zod 校验 + workspaceId 强制覆盖（见 import-data.spec 的伪造测试）。

### A09 日志与监控 — ✅ 基本完备

- 结构化日志（pino/log level env）；审计日志表（谁/何时/对什么/改了什么，前端设置页可查）。
- 可观测栈（OpenTelemetry/Sentry）按宪法是部署阶段事项，本轮不引依赖。

### A10 SSRF — 🔧 本轮加固 1 项（含未来决策）

- **风险面**：AI baseUrl 是用户可控的服务端出网目标（`PUT /v1/ai/config`），适配器据此 `fetch`。
- **修复**：`@atlas/core` 新增 `isBlockedAiEndpoint`——封锁云元数据端点（`169.254.169.254`、`metadata.google.internal`、`metadata.goog`、`fd00:ec2::254`）及整段 IPv4 链路本地（`169.254.0.0/16`）与 IPv6 链路本地（`fe80::/10`）；适配器 `complete()` 前置校验，命中即抛错。单测 3 组（封锁/放行/非法 URL）。
- **决策记录**：不封 `127.0.0.1`/局域网——本地 mock 上游与自建代理是合法用法（当前单租户自用，用户配自己的密钥指向自己的服务）。**多租户售卖前必须升级**为"出网代理 + 私网段全白名单"（写入阶段 7 前置条件）。

2. 全私网段出网白名单 → 阶段 7 多租户化之前

4. 依赖审计纳入 CI → GitHub Actions 接入时加 `pnpm audit --prod` 步骤
