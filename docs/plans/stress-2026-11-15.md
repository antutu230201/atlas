# 10 万级压测复测记录（2026-11-15）

> 对应 `docs/plans/system-optimization-next-steps.md` §P2 与路线图阶段 4 的"10 万级压测复测 ⬜"——本轮收口。
> 原则：隔离库、可复制命令、同口径对比；只在热点证据明确时改查询/索引，不为速度绕过租户过滤与 RLS。

## 复制命令

```bash
pnpm --filter @atlas/api exec vitest run test/integration/stress-100k.spec.ts
# 预算断言失败即压测回归（<100ms / <150ms / 导出 <10s）
```

- 测试库：**5433 隔离实例**（`pgdata-test`，global-setup 每轮截断），绝不触碰 5432 正式库
- 种子：10 万条站内通知（未读 ≈ 99.8%，贴近最坏未读占比）+ 1 千条待办 + 1 千条笔记，单条 `generate_series` SQL 批量注入
- 采样：每端点预热 1 次后连打 20 次，取 p50/p95/max（进程内 hrtime，含 HTTP + JSON 序列化）

## 环境

- 机器：本机开发机（Windows 10.0.26320 x64），Node v24.22.1，embedded-postgres 17
- 构建：测试夹具以真实配置启动完整 Nest 应用（随机端口），模块 dist 为当前构建产物
- 数据量：notifications 100,000 行 / todo 1,000 行 / note 1,000 行（单用户单工作空间）

## 结果（全部达标，无需热点修复）

| 端点                                         | 数据量       | p50  | p95                        | 预算      |
| -------------------------------------------- | ------------ | ---- | -------------------------- | --------- |
| GET /notifications（首页 20 条）             | 10 万行      | 26ms | **27ms**                   | <100ms ✅ |
| GET /notifications（深页 cursor≈9.8 万行处） | 10 万行      | 14ms | **22ms**                   | <150ms ✅ |
| GET /notifications/unread-count              | ≈9.98 万未读 | 14ms | **14ms**                   | <100ms ✅ |
| GET /notifications/quiet-hours               | —            | 2ms  | **2ms**                    | <100ms ✅ |
| POST todo_notes/list（limit 100）            | 1 千行       | 8ms  | **12ms**                   | <100ms ✅ |
| POST sample_note/list（limit 100）           | 1 千行       | 6ms  | **56ms**                   | <100ms ✅ |
| GET /notifications/export（全量 JSON）       | 10 万行      | —    | **752ms / 23.6MB**（单次） | <10s ✅   |

## 结论与证据

1. **深分页无衰减**：游标 `(created_at, id)` 行比较走 `notification_user_created_idx`，第 9.8 万行处的页读 p95=22ms，比首页还快（无 OFFSET 扫描）。
2. **未读数无需新索引**：9.98 万未读的 count 在现有 `notification_user_created_idx` 前缀扫描下 p95=14ms——"未读数要加 partial index"的直觉被证据否定，按"热点证据明确才改"原则**不加**。
3. **宪法 §4 导出在 10 万行规模可用**：752ms 序列化 23.6MB JSON；前端下载走 Blob 不落服务端内存峰值之外的开销。
4. 待办/笔记 1 千行列表 p95 均 <60ms，limit 100 的截断策略在合理数据量下安全。

## 说明

- 压测数据只存在于隔离测试库，spec afterAll 主动清理 + 下轮 global-setup 截断双保险；不写入日志、截图或夹具。
- 未测前端 DOM 挂载数：通知页/待办页均为服务端分页（20–100 条/页），DOM 挂载量与数据总量无关，已在列表设计上排除该风险。
- 笔记列表 p95=56ms 的离群（p50=6ms）为单次 GC/调度抖动，20 样本内 max 与 p95 重合，不构成热点证据。
