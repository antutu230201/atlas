> 配套阅读顺序：[AGENTS.md](../../AGENTS.md)（宪法）→ [docs/roadmap.md](../roadmap.md)（进度）→ 本文（环境）→ [docs/guide/如何开发一个模块.md](./如何开发一个模块.md)（加功能）。

## 1. 新机器冷启动

```bash
corepack enable            # 启用 pnpm
pnpm install               # 安装依赖（自动下载内嵌 PostgreSQL 二进制）
pnpm build                 # 【必须】产出模块 dist —— 模块包以 dist/index.js 被 API 动态加载，
                           # dist 不入库（gitignore），跳过这步 API 会报"模块发现失败/500"
pnpm dev                   # web + api + 内嵌 PostgreSQL 一条命令
```

- 验证：`http://localhost:PORT/v1/health` 的 api/database/queue/cache/storage 五项全"正常"。
- 首次注册账号 → 建工作空间 → 设置→模块→启用（todo_notes / dashboard）。
- 国内 corepack 慢：`COREPACK_NPM_REGISTRY=https://registry.npmmirror.com corepack enable`。

## 2. 端口与多实例（踩过的坑）

| 变量/脚本                       | 作用                                                                               |
| ------------------------------- | ---------------------------------------------------------------------------------- |
| `PORT`                          | web 的 dev/start 端口（默认 3000；`apps/web/package.json` 已遵循）                 |
| `E2E_API_PORT` / `E2E_WEB_PORT` | e2e 自带 dev server 的端口（默认 3001/3000）                                       |
| `CORS_ORIGIN`                   | API 允许的前端来源，**逗号分隔**；web 换端口后必须把新 origin 加进 `apps/api/.env` |

- **同一仓库同时只能跑一个 `next dev`**：后启动者会因锁文件直接退出（Next 16 行为），谁在跑先查端口。
- 历史教训：本机 3000 一度被无关项目长期占用 → 所有"端口写死"的地方都要可配置；`apps/api/.env` 不入库，换机后按需重建（样例见根目录 `.env.example`，含 CORS_ORIGIN 说明）。
- 跑全量 `pnpm test` / `pnpm e2e` **前先停掉正在跑的 dev 服务**：测试与 dev 共用 5432 内嵌 PG，并存会出现 ECONNRESET 假失败（2026-11-05 实测踩坑）。

## 3. 内嵌 PostgreSQL（ADR-0002）

- 数据目录：`apps/api/.local/pgdata`（gitignore，删掉即重置，重启自动 initdb + 迁移）。
- 5432 已有实例时直接复用，不重复拉起。
- 数据库直连（排查用）：`postgres://atlas:atlas@localhost:5432/atlas`（管理）/ `atlas_app:atlas_app`（应用，RLS 约束）。

## 4. 质量门（提交前全跑，宪法 §7）

```bash
pnpm typecheck && pnpm lint && pnpm test

E2E_API_PORT=3011 E2E_WEB_PORT=3010 pnpm e2e   # 端口被占时这样覆盖
```

## 5. 已修过的坑（防复发，改代码前先看）

| 坑                               | 现象                                              | 正确做法                                                                                                     |
| -------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Tailwind `@source` 目录型通配    | 模块专用类全部不生成（图标巨型化、grid 塌成单列） | 必须文件级 glob：`modules/**/src/web/**/*.{ts,tsx}`（globals.css）                                           |
| 新模块忘加 `transpilePackages`   | 全站 (app) 路由 404（裸 `<pre>404</pre>`）        | `apps/web/next.config.ts` 同步登记新包                                                                       |
| 模块迁移只在**启用时**执行       | 改了迁移文件不生效                                | 设置页停用→再启用该模块；或删 `.local/pgdata` 重置                                                           |
| 事件派发失败静默重试             | 接口不动、无日志                                  | 查 `platform.event` 表的 `status/attempts/last_error`（psql 不在内嵌包里，用 apps/api 下 `node -e` + pg 查） |
| 模块注册表负缓存（已修 634552b） | 一次发现失败进程内永远 500                        | 失败即清缓存自动重试；新模块 dist 构建完无需重启 API                                                         |
| 玻璃态写死白色 rgba              | 暗色主题侧栏/顶栏发白不可读                       | 一律用 `glass`/`glass-strong` 工具类 + tokens.css 的 `--glass-*`/`--screen-*` 变量                           |

## 6. 项目结构速查

- `packages/`：tokens（唯一视觉来源）/ ui（Radix 基元组件）/ sdk（模块协议）/ core / config
- `apps/web`：Next.js 前端；模块页挂载点在 `src/lib/module-registry.tsx`（新模块带界面必须登记）
- `apps/api`：NestJS 内核 + 事件总线 + AI 层（`ctx.ai.complete`）
- `modules/`：业务模块（manifest + server + web + migrations）；模块间只走事件总线，禁止互读表
