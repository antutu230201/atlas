# 如何开发一个模块

> 目标：照着本指南，30 分钟内做出一个可用的新模块。**全程不需要修改内核任何代码。**
> 活教材：`modules/sample-note`（阶段 2b/2c 验收模块）——卡住的时候看它怎么写。

## 0. 模块是什么

模块 = 一个工作区包（`@atlas/module-*`），声明 manifest（能力与需求）+ actions（动作），自带数据库 schema 与迁移。内核在运行时发现它、启用它、按权限分发对它的调用。

铁律回顾（AGENTS.md §5）：模块之间不互相引用；业务表必须带 `workspace_id`；写操作有审计；删除默认软删除；外部服务走适配器。

## 1. 目录结构与包配置

```
modules/<your-module>/            # 目录名用连字符；包名用 @atlas/module-<your-module>
├─ package.json                   # name: "@atlas/module-<your-module>"，main: dist/index.js
├─ tsconfig.json                  # extends packages/config/tsconfig/library.json
├─ drizzle.config.ts              # schemaFilter 指向你的 schema
├─ src/
│  ├─ index.ts                    # 导出 definition（manifest + actions）
│  └─ db/schema.ts                # 你的表（schema 固定为 modules.<name>）
└─ migrations/                    # drizzle-kit 生成的迁移（含 RLS 模板，见第 3 节）
```

`package.json` 要点：

```json
{
  "name": "@atlas/module-<your-module>",
  "main": "dist/index.js",
  "scripts": { "build": "tsc -p tsconfig.json", "db:generate": "drizzle-kit generate" },
  "dependencies": { "@atlas/sdk": "workspace:*", "drizzle-orm": "^0.45.4", "zod": "^4.1.0" }
}
```

然后两步接线（这是仅有的两处"仓库级"改动，均不属于内核代码）：

1. `apps/api/package.json` 的 dependencies 加 `"@atlas/module-<your-module>": "workspace:*"`（内核靠它动态发现模块）；
2. `pnpm install`。

## 2. manifest：声明你要什么

```ts
import { moduleManifestSchema } from '@atlas/sdk';

const manifest = moduleManifestSchema.parse({
  name: 'your_module', // = 数据库 schema 名（modules.your_module）
  version: '0.1.0',
  title: '你的模块',
  description: '一句话说明',
  permissions: ['your_module:read', 'your_module:write'],
  dependsOn: [], // 依赖的模块；启用时自动按序启用
  routes: [{ path: 'list', title: '列表', nav: { order: 10 } }],
  settings: [{ key: 'maxItems', label: '上限', type: 'number', default: 100 }],
  events: { publishes: ['your_module.created'], subscribes: [] },
  migrations: 'migrations',
});
```

## 3. 数据库：schema + 迁移（必须包含 RLS 模板）

`src/db/schema.ts` 里所有表放 `modules.<name>` schema，**每张表必须带 workspace_id**：

```ts
export const moduleSchema = pgSchema('modules.your_module');
export const item = moduleSchema.table(
  'item',
  {
    id: uuid('id').primaryKey().defaultRandom(),
    workspaceId: uuid('workspace_id').notNull(),
    /* ... */
  },
  (t) => [index('item_workspace_idx').on(t.workspaceId)],
);
```

`pnpm --filter @atlas/module-<your-module> db:generate` 生成 0000 迁移后，**再手写一个 0001_rls.sql 并在 migrations/meta/\_journal.json 里登记**（内容照抄 sample-note，替换 schema 名）——缺了它，运行时角色将无权访问你的表，且没有租户隔离兜底：

```sql
GRANT USAGE ON SCHEMA "modules.your_module" TO atlas_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA "modules.your_module" TO atlas_app;
ALTER TABLE "modules.your_module"."item" ENABLE ROW LEVEL SECURITY;
CREATE POLICY item_tenant ON "modules.your_module"."item"
  USING (workspace_id IN (SELECT platform.user_workspace_ids()))
  WITH CHECK (workspace_id IN (SELECT platform.user_workspace_ids()));
```

## 4. actions：模块的"接口"

动作经内核网关分发：`POST /v1/modules/workspaces/:slug/<name>/call/<action>`。
**一个调用 = 一个租户事务**；`ctx.db` 已按当前用户绑定 RLS；`ctx.events.publish` 与业务写入同事务落 outbox。

```ts
import type { ModuleDefinition } from '@atlas/sdk';

export const definition: ModuleDefinition = {
  manifest,
  actions: {
    list: {
      // 键名 = URL 里的 action
      permission: 'your_module:read', // 权限点（guest 只读，member+ 读写）
      handler: async (ctx, input) => {
        const rows = await ctx.db.select().from(item).where(eq(item.workspaceId, ctx.workspaceId)); // 仍要显式过滤 workspace_id
        return { items: rows };
      },
    },
    create: {
      permission: 'your_module:write',
      handler: async (ctx, input) => {
        const parsed = createSchema.safeParse(input); // 输入必须 schema 校验
        if (!parsed.success) throw new Error('输入不合法');
        const rows = await ctx.db
          .insert(item)
          .values({ ...parsed.data, workspaceId: ctx.workspaceId })
          .returning();
        await ctx.events.publish('your_module.created', { itemId: rows[0]!.id }); // outbox 同事务
        return rows[0];
      },
    },
  },
};
```

ModuleContext 全量能力：`ctx.db`（租户事务执行器）、`ctx.can(permission)`、`ctx.settings.get()/set()`（工作空间级模块设置）、`ctx.events.publish()`、`ctx.userId/workspaceId/role`。

## 5. 订阅别人的事件

```ts
events: { publishes: [...], subscribes: [{ event: 'todo.completed', handler: 'onTodoCompleted' }] }
```

`handler` 是你 actions 里的键。派发语义是 **at-least-once**（投递失败退避重试直至死信）——handler 必须幂等，用 `payload` 里的 ID 去重。模块停用期间的事件不会补投给你。

## 6. 启用与调用

```bash
# owner/admin 在某工作空间启用（依赖模块自动按序启用，迁移自动执行）
curl -X POST .../v1/modules/workspaces/<slug>/your_module/enable -b cookie.txt
# 调用动作
curl -X POST .../v1/modules/workspaces/<slug>/your_module/call/list -b cookie.txt
```

停用：数据保留；有其他启用中的模块依赖你时会被拒绝。重新启用后数据仍在。

## 7. 测试与验收清单
